# Investigation: LiveKit WebRTC Version Resolution and ElevenLabs Local Swift Package in Xcode

## 1. Background and environment

We are investigating a Swift Package Manager (SPM) dependency-resolution issue encountered by developers while building an iOS application in Xcode.

Our DevOps team is migrating Swift Package Manager dependencies to an internal Nexus Repository Manager.

**Nexus environment:**
- Product: Sonatype Nexus Repository Manager Community Edition
- Version: 3.95.0-07
- Repository name: `swift-proxy`
- Repository URL: `https://mod-fintas-snn03.corp.boubyan.com:8443/repository/swift-proxy/`
- IP: 10.1.21.81
- Repository type: Swift proxy
- Upstream source: GitHub-hosted Swift packages

The developer reported problems resolving LiveKit dependencies, particularly `livekit.webrtc-xcframework`.

The original findings were:

| Package | Version | Observed result |
|---|---|---|
| `elevenlabs.elevenlabs-swift-sdk` | 3.0.0 | Successfully resolves |
| `livekit.client-sdk-swift` | 2.19.0 | Found |
| `livekit.livekit-ffi-xcframework` | 0.13.0 | Intermittent HTTP 500 errors, followed by HTTP 200 |
| `livekit.webrtc-xcframework` | 150.7871.4 | Not found |
| `swift-log` | — | Found |
| `swift-protobuf` | — | Found |

## 2. Issue 1: ElevenLabs cannot resolve the LiveKit WebRTC version

We investigated the Nexus Swift proxy directly using curl.

Command executed:

```bash
curl -v \
-H "Accept: application/vnd.swift.registry.v1+json" \
-u "s_banana" \
"https://mod-fintas-snn03.corp.boubyan.com:8443/repository/swift-proxy/livekit/webrtc-xcframework"
```

The response successfully returned the available releases, including:

```text
150.7871.04
```

However, the response did not contain:

```text
150.7871.4
```

This suggests that Nexus can retrieve the WebRTC package's release information, but the exact version requested by the developer is not advertised under the same version string.

### Further investigation

The developer explained that ElevenLabs is requesting WebRTC version `150.7871.4`.

We asked the developer to inspect the local ElevenLabs package manifest:

```text
[path/to/LocalStorage/ElevenLabs/Package.swift]
```

The developer confirmed that the reference to `150.7871.4` appears in the package's dependency information.

We also attempted to clear SwiftPM's registry configuration/cache by deleting the following directory:

```text
~/Library/org.swift.swiftpm/configurations
```

After retrying, Xcode still did not display the ElevenLabs local package as an expected package dependency.

### Questions requiring investigation

1. Does the exact LiveKit WebRTC version `150.7871.4` actually exist as a published release, or is the intended published version `150.7871.04`?
2. Why does ElevenLabs reference `150.7871.4` when Nexus advertises `150.7871.04`?
3. Is this a Semantic Versioning issue, a SwiftPM registry lookup issue, a Nexus implementation limitation, or a problem with the ElevenLabs package manifest?
4. Does SwiftPM treat `150.7871.4` and `150.7871.04` as equivalent versions, or does it require an exact version-string match during registry resolution?
5. Is there a legitimate way to resolve this through Nexus without modifying the upstream ElevenLabs package?
6. Does a newer Nexus Community Edition release address this behaviour?

Please investigate using the official Swift Package Registry specification, SwiftPM documentation/source code, Nexus documentation/source code, and the relevant LiveKit and ElevenLabs package manifests.

## 3. Issue 2: Xcode does not recognise the local ElevenLabs Package.swift

The developer was instructed to navigate to the local ElevenLabs package directory:

```text
[path/to/ElevenLabs/localpackage/]
```

The directory contains a `Package.swift` manifest.

The intention was to open this local package directly in Xcode and inspect its dependencies, particularly the reference to LiveKit WebRTC version `150.7871.4`.

However, opening the local `Package.swift` does not result in the package appearing as an expected Swift package in Xcode.

We also attempted to remove the SwiftPM registry configuration directory:

```text
~/Library/org.swift.swiftpm/configurations
```

Then retried the operation, but the package still did not appear.

### Questions requiring investigation

1. What is the correct way to open a standalone local Swift package in Xcode?
2. Should we open the `Package.swift` file directly, or should we open the package's containing directory?
3. What conditions must be met for Xcode to recognise a local directory as a valid Swift package?
4. Could the package's `swift-tools-version`, manifest syntax, directory structure, or dependency declarations prevent Xcode from recognising it?
5. How can we inspect the package's declared dependencies and determine exactly where the WebRTC version requirement originates?
6. How can we distinguish between a package that is not recognised by Xcode and a package that is recognised but fails dependency resolution?

Please provide the correct diagnostic and opening procedure, rather than assuming the issue is caused by the registry cache.

## 4. Important distinction: Network connectivity

During a separate attempt to build the developer-provided Xcode project, the build failed while fetching the Git submodule:

```text
https://github.com/livekit/protocol.git
```

The error was:

```text
Failed to connect to github.com port 443
Couldn't connect to server
```

We tested connectivity from the Mac using curl, and both HTTPS and telnet-style connectivity tests to GitHub failed.

There is no proxy configured on that Mac.

This is a separate network connectivity obstacle. It prevented the Xcode project from completing dependency resolution and is not, by itself, evidence of a Nexus registry issue.

Do not conflate this GitHub connectivity problem with the WebRTC version mismatch.
